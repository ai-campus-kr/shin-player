# v1.1.0 쇼츠 편집 검증

2026-09-23, Windows x64 / .NET 8 WPF. 최종 소스의 자체 포함 빌드에서 **98개 통합 검사 통과, 실패 0, 프로세스 종료 코드 0, 완료 표식 PASS**를 확인했습니다. 경고를 오류로 처리한 컴파일도 오류·경고 0개입니다.

## 변경과 검증

| 영역 | 확인한 동작 |
|---|---|
| 원본 영역 선택 | 정방향·역방향 드래그, 손잡이 잡은 위치 보존, 내부 이동과 경계 제한, 가장자리 크기 변경, 최소 2% 영역. 98개 위치에서 아주 짧은 드래그와 모서리 조정을 검사했습니다. 최소 크기의 부동소수점 반올림을 보정했습니다. |
| 확대·구도 | 100~400%, 휠 조작·슬라이더 동기화, 전체 보이기와 채우기에서 이동. 선택 영역은 구간 전체에 같은 구도로 적용합니다. |
| 미리보기와 출력 | 임의 영역과 확대·이동, 90도 회전 원본, 높이 2%의 얇은 영역 등 네 경우의 실제 MP4와 미리보기를 비교했습니다. 각 209개 표본점 중 92% 이상이 채널별 차이 35 미만이어야 통과합니다. 완전히 동일한 디코딩 픽셀을 요구하는 검사는 아닙니다. |
| 글꼴 | 여섯 글꼴이 시스템 대체 글꼴이 아닌 내장 리소스로 해석되는지, 한글 글리프 포함 여부, 서로 다른 한글 렌더링과 사용자 RGB 출력 픽셀을 검사했습니다. |
| 입력·저장 | 글꼴 선택, 18색과 직접 HEX 입력, 잘못된 색상으로 저장 방지, 변경 후 재저장 안내, 실패 후 재시도·취소·창 닫기와 미완성 파일 정리를 확인했습니다. |
| 화면과 기존 동작 | 네 테마·최소 창에서 미리보기와 고정 완료 패널, 쇼츠 창 종료 후 플레이어 주소창 유지, 기존 영상 디코딩·탐색·배속·음량·자막·GIF·채팅·WebView2 검사를 통과했습니다. |

여섯 글꼴은 원본 TTF를 수정 없이 내장했습니다. 고정한 원본 SHA256과 OFL 고지를 검증했고 출처·저작권·라이선스는 `Assets/Fonts/` 및 배포본 `licenses/fonts/`에 포함합니다. [외부 구성요소](../THIRD-PARTY-NOTICES.md), [실제 화면과 제작 방식](screenshots/v1.1.0/README.md).

## 재현

```powershell
dotnet build src/ShinPlayer/ShinPlayer.csproj -c Release -p:IncludeNativeEngine=false --warnaserror
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -SkipNative
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test.ps1 -ReportName verification-v1.1.0-release
```

최종 보고서는 로컬 `artifacts/verification-v1.1.0-release/results.json`과 `complete.txt`입니다. 원본 보고서의 개인 경로는 공개하지 않습니다. 검사별 메인 창의 표시·상태·활성화·주소창 크기를 기록하도록 진단 정보를 보강했습니다.

초기 전체 검사 한 번에서 이후 주소창의 포커스·표시 관련 검사 4개가 실패했습니다. 상태를 기록한 진단 실행과 이후 두 전체 실행에서는 모두 98개가 통과했고, 확정 원인은 재현하지 못했습니다. 쇼츠 종료 후 메인 창·주소창이 보이고 활성 상태인지 검사도 추가했습니다. 이 기록을 모든 환경에서 재발하지 않는다는 보장으로 해석하지 않습니다.

## 범위

합성 영상을 사용한 실제 WPF/libmpv·FFmpeg 검사입니다. API에는 대체 응답·격리된 테스트 키를 사용했고 실제 OpenAI API를 호출하지 않았습니다. WebView2는 격리된 페이지로 검증했으며 실제 유튜브 사이트 재검사는 이번 변경 범위가 아닙니다. GIF·쇼츠는 로컬 영상 전용을 유지합니다.

WPF 이벤트와 좌표 검증은 물리 마우스·실제 모니터 DPI 변경 검사가 아닙니다. 기본 Windows 색상 대화상자의 물리 입력까지 자동화한 것은 아닙니다. WPF 이미지와 libmpv native 영상 표면을 별개로 확인했으며, 합성 입력 결과로 모든 영상 형식·장시간 고해상도 처리 성능을 보장하지 않습니다.
